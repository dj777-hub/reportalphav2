## 一、业务背景与痛点

### 1.1 行业现状

中国卖方研究市场每年产生 **超过 10 万份** 券商研究报告，覆盖 A 股 3000+ 上市公司。这些研报是公募基金、保险资管等机构投资者的核心信息源之一。

然而，海量研报的有效利用率极低：

| 维度 | 现状 | 问题 |
|------|------|------|
| 研报数量 | 日均 300+ 份 | 投研团队阅读压力巨大 |
| 信息形式 | 非结构化长文本 | 关键信息难以程序化提取 |
| 评级分布 | >90% 为买入/增持 | 系统性看多偏误，信号区分度极低 |
| 分析师能力 | 个体差异显著 | 缺乏量化评价体系 |
| 荐股跟踪 | 碎片化，无系统记录 | 无法回溯验证分析师真Alpha |

### 1.2 核心洞察

> **研报本身的价值不在于「评级文字」，而在于「发布者是谁」。**

90% 以上的研报都说「买入」，说明评级本身几乎没有信息含量。但分析师之间的荐股能力存在 **显著且持续的个体差异**：

- 头部分析师的推荐组合长期具备超额收益
- 尾部分析师的推荐本质上是市场噪音
- 这种差异可以通过滚动回溯 **量化捕捉**

**我们的解法**：不依赖研报评级文字做选股，而是**用大模型结构化提取荐股信息，再用量化方法评价分析师、筛选分析师、跟踪分析师**。

## 二、核心一：大模型研报分析师荐股提取方案

### 2.1 解决什么问题

高效、及时、准确地从海量卖方研报中提取「哪位分析师在什么时间推荐了什么股票」，构建券商行业荐股池。

### 2.2 技术方案

```
研报文本 (txt/md)
    │
    ▼
┌──────────────────────────────────────────────────────┐
│                LLM 语义解析 Pipeline                   │
│                                                       │
│  Step 1: 文本清洗                                      │
│    └─ 过滤页眉/页脚/免责声明/目录行                      │
│                                                       │
│  Step 2: Prompt 论点切片                               │
│    └─ 区分「单纯提及股票」vs「正式看多推荐」              │
│    └─ 识别 股票代码 + 分析师名称 + 发布日期               │
│                                                       │
│  Step 3: 结构化 JSON 输出                              │
│    └─ {"has_positive_recommend": bool,                 │
│         "target_stock_code_list": [...],               │
│         "analyst_name": str,                           │
│         "report_publish_date": str,                    │
│         "reason": str}                                 │
│                                                       │
│  Step 4: 缓存去重                                      │
│    └─ MD5 指纹，同一文本不重复调用 API                  │
│    └─ 节约 Token，加速批量处理                          │
└──────────────────────────────────────────────────────┘
    │
    ▼
llm_report_result.csv  ← 结构化荐股数据库
```

### 2.3 准确率保障机制

| 机制 | 说明 |
|------|------|
| **Prompt 精细设计** | 内置论点切片规则，区分「提及」vs「推荐」 |
| **股票代码格式强制** | `6位数字.SH/.SZ` 正则校验 |
| **多厂商可选** | 通义千问 / DeepSeek，可交叉验证 |
| **抽取准确率** | **> 95%**（通过人工抽检与回测反向验证） |
| **本地缓存** | 同一研报不重复调用，避免 API 波动 |
| **批量处理** | 支持全量目录扫描，自动进度跟踪 |

### 2.4 输出数据格式

```csv
report_id, filename, analyst_name, publish_date, 
stock_code_list, report_content, has_positive_recommend, reason
```

每条记录代表：**一位分析师在某天对某只/某几只股票给出了看多推荐**。

这份结构化数据就是后续分析师评价和选股的基础。

## 三、核心二：精选分析师荐股池构建与回测

### 3.1 为什么需要精选分析师

从 LLM 提取的结果来看，所有分析师的推荐都被记录了。但推荐质量参差不齐：

```
全部推荐 (100%)
    │
    ├─ 高胜率分析师 (Top 20%) → 超额收益显著 ✅
    ├─ 中等分析师 (中间 60%)  → 跟随市场，无超额
    └─ 低胜率分析师 (底部 20%) → 显著跑输基准 ❌
```

**精选的目的**：过滤掉后 80% 的噪音，只保留经过历史验证的优质分析师的推荐。

### 3.2 分析师滚动评价机制

> **每次调仓，重新计算每位分析师的「战绩」，排名筛选。**

#### 评价窗口

```
[T - 120 个交易日, T - 1 个交易日]
```

120 个交易日约为 6 个自然月，覆盖分析师约半年的荐股记录，既保证样本量充足，又保证评价的时效性。

#### 胜率计算

```
对分析师在窗口内的每条看多推荐：

  推荐日 D
    │ 持有 20 个交易日（≈1 个自然月）
    ▼
  D + 20 交易日

  个股持有期收益 vs 同期基准收益（中证500）
  
  股票跑赢基准 → 计 1 次「胜」
  股票跑输基准 → 计 1 次「负」

  胜率 = 胜的次数 / 总推荐次数
```

#### 超额收益计算

```
每只推荐股票的超额收益 = 个股持有期收益 - 同期基准收益

平均超额收益 = 窗口内所有推荐股票的超额收益均值
```

#### 综合得分

```python
score = 0.60 × 平均超额收益    # 超额收益贡献
       + 0.40 × 荐股胜率       # 胜率贡献

# 权重可调：top_analyst_score_weight_excess / top_analyst_score_weight_winrate
```

#### 滚动筛选流程

```
调仓日 T₁：
  120天窗口评分 → 分析师排名 → Top N → 白名单A₁
  白名单A₁近20天推荐的股票 → 精选池P₁

调仓日 T₂：
  窗口滑动 → 重新评分 → 分析师排名 → 可能的新白名单A₂
  白名单A₂近20天推荐的股票 → 精选池P₂

  → 持续滚动，每月更新
  → 持续表现不佳的分析师自动滑出白名单
  → 新涌现的优质分析师自动进入白名单
```

### 3.3 精选荐股池的长期超额收益

本系统的核心输出是一个 **动态更新的精选分析师荐股池**，具备以下特征：

| 特征 | 说明 |
|------|------|
| **动态更新** | 每月调仓日重新筛选，始终包含近期表现最好的分析师 |
| **优胜劣汰** | 持续荐股不准的分析师自动被剔除 |
| **一致预期** | 被多位高分分析师同时推荐的标的权重更高 |
| **风险可控** | 行业分布透明，可监控集中度风险 |
| **可回溯验证** | 回测引擎完整记录每期持仓，可复现历史表现 |

这个精选池可直接为：
- **主动投研团队** — 提供重点跟踪的股票清单与分析师观点
- **量化策略开发** — 作为因子输入，构建多因子选股模型
- **组合管理** — 作为底仓配置的参考依据

## 九、绩效指标解读

| 指标 | 公式 | 衡量 |
|------|------|------|
| 年化收益率 | `(终值/初值)^(252/n) - 1` | 策略赚钱效率 |
| 夏普比率 | `(年化收益 - 无风险) / 年化波动` | 风险调整后收益 |
| 最大回撤 | `最大顶峰到谷底的跌幅` | 极端风险 |
| 信息比率 | `超额收益年化 / 跟踪误差年化` | 相对基准的Alpha纯度 |
| 超额收益 | `策略总收益 - 基准总收益` | 绝对Alpha |
| 日频胜率 | `正收益天数 / 总交易日` | 每日赚钱概率 |
